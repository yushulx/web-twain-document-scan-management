## 将 document_annotation 示例的 Dynamsoft SDK 升级到最新版

用户要求把工程里用到的 Dynamsoft SDK 升级到最新版本。工作目录 = `examples/document_annotation`。

### 版本变更
| SDK | 旧 | 新 | 位置 |
|---|---|---|---|
| dynamsoft-capture-vision-bundle (DCV) | 3.0.3001 | **3.6.3200** | index.html |
| dynamsoft-document-viewer (DDV) | 3.0.0 | **5.0.0** | index.html（css/js + 2 个新插件） |
| dwt (Dynamic Web TWAIN) | 未固定版本 | **19.4.3**（固定） | index.html + main.js `DWT.ResourcesPath` |

非 Dynamsoft 依赖未动：bwip-js 4.1.2 / tesseract.js 5.0.2 / pdf.js 3.11.174 / jspdf 2.5.1 / utif2 4.1.0。

### DDV 3.0.0 → 5.0.0 是破坏性变更：拆成插件架构
- 注解能力移到 `dist/plugins/ddv-plugin-annotation.js`，PDF/图像解析移到 `dist/plugins/ddv-plugin-image-pdf.js`。
- 必须在 `Core.init()` **之前** 调用 `Dynamsoft.DDV.use(Dynamsoft.DDV.AnnotationPlugin)` 与 `Dynamsoft.DDV.use(Dynamsoft.DDV.ImagePdfParserPlugin)`。
- DDV 5.0.0 已是独立产品，不再共用 DCV 的 LicenseManager，需要单独设 `Dynamsoft.DDV.Core.license = license`。
- 后果：`Dynamsoft.DDV.annotationManager` 在插件注册前是 `undefined`，因此 main.js 里原本**脚本顶层**执行的 `annotationManager.on("annotationsModified", ...)` 会抛 TypeError，导致整个 main.js 中断。已改为函数 `registerAnnotationEvents()`，在 `activate()` 里调用。

### DCV 3.0.3001 → 3.6.3200 的破坏性变更
1. `CaptureVisionRouter.appendModelBuffer()` 改名为 **`appendDLModelBuffer()`**（参数不变，仍传模型名字符串）。
2. code spec `AAMVA_DL_ID_WITH_MAG_STRIPE` 已被合并进 `AAMVA_DL_ID`；`dynamsoft-capture-vision-data` 从 1.0.1 的 `.dcpres` 多文件变成 1.2.x 的单个 `AAMVA_DL_ID.data`。继续 `loadSpec("AAMVA_DL_ID_WITH_MAG_STRIPE")` 会报 `[-10005] The specified file could not be found.`，已删除该行。
3. 模型/解析资源/字符资源改由独立 npm 包 `dynamsoft-capture-vision-data` 提供（`models/`、`parser-resources/`、`char-resources/`），通过 `engineResourcePaths.dcvData` 暴露。
4. 新版 dist 只保留 `dynamsoft-capture-vision-bundle-ml*.wasm`（去掉了非 ML 的 wasm）。

## 补修：升级后点击 "Sources" 按钮报错（第 4 处破坏性变更）

用户反馈点击工具栏 Sources 按钮（`tooltip: "Sources: File, Camera, Scanner"`，class `.ddv-load-image`）直接报错：
`Uncaught TypeError: Cannot read properties of undefined (reading 'stopPropagation')  at toggleDropdown (main.js)`。

**根因**：DDV 自定义元素事件的派发方式变了。对比两个版本的 `initEvents()`：
- DDV 3.0.0：`this.on(e, function(){ var args=[...arguments]; Gn(i) ? t.$emit(i, args) : ... })` —— 把监听参数**包成一个数组**再 emit，所以 handler 收到 `e = [domEvent]`，`e[0]` 才是 DOM 事件。
- DDV 5.0.0：`this.on(e, ((...args)=>{ Pn(t) ? this.$emit(t, ...args) : ... }))` —— **展开**参数 emit，handler 直接收到 `e = domEvent`，于是 `e[0]` 变成 `undefined`。

**修复**（main.js `toggleDropdown`）：
```js
const domEvent = Array.isArray(e) ? e[0] : e;
if (domEvent && typeof domEvent.stopPropagation === "function") domEvent.stopPropagation();
```
同时兼容 3.x 数组形态、5.x 直接形态、以及完全没有参数的情况。

**排查确认**：`editViewer.on()` 注册的 11 个 handler 里，只有 `toggleDropdown` 带参数，其余（addQr/download/flatten/scanBarcode/clearAll/sign/detectDocument/recognizeText/popScanner）都是无参函数，不受影响。

**验证**：
1. 把 main.js 里真实的 `toggleDropdown` 抽出来在 Node vm 里跑：旧代码遇到 DDV 5.0.0 形态**精确复现**了用户那句报错；新代码在 4 种参数形态下均不抛错且正常创建菜单。
2. 浏览器端到端：`toggleDropdown(new MouseEvent('click',{bubbles:true}))` → `OK menu=block`，控制台 errors 为空，下拉菜单 4 个按钮（File / Camera / Scanner (RESTful) / Scanner (Dynamic Web TWAIN)）齐全。

### 环境笔记（避免重复踩坑）
- agent-browser 在本机会话偶发失效：一旦浏览器进程退出，后续 `get url` / `eval` 会**永久挂起**，且 `timeout` 杀不掉（Node 忽略 SIGTERM），必须 `TaskStop` 手动清理后台任务。判断会话是否存活：`agent-browser eval "1+1"`。
- 因此**验证脚本尽量放后台跑**（`run_in_background`），别在前台等。
- 对纯函数类改动，用 Node `vm` 抽出真实源码做单元验证，比反复开浏览器快且稳定。
- `agent-browser find <title> click` 这类真实点击在会话不健康时会连带把会话打死。

## 补修 2：Detect Document 报 `'annotationOptions' is invalid`（第 5、6 处问题，均为原有 bug）

用户反馈点 Detect 后报错。先剥离噪音：26× `Could not establish connection. Receiving end does not exist`、`polyfills.js / main.js:119`、`favicon.ico 404`、`No response` 全部是 **Chrome 扩展 + 预览服务器注入**的，与工程无关。

真正的错误：
```
ddv.js:11 Uncaught (in promise) Error: AnnotationManager.createAnnotation: 'annotationOptions' is invalid.
  at kl (ddv-plugin-annotation.js)
  at createAnnotation (ddv-plugin-annotation.js)
  at scanBarcode (main.js:1083) / recognizeText (main.js:1351) / (anonymous) (main.js:281)
```

### 根因：`pageData.display` 是**方法**，不是属性
`IPageData` 定义为 `display(): Promise<PageImageInfo>`（3.x 与 5.x 完全一致，是**方法**）。
代码里 6 处写了 `pageData.display.width` / `.height` → 恒为 `undefined`
→ 坐标换算 `p.x / undefined * mediaBox.width` = **NaN**
→ DDV 的注解校验拒绝 NaN（`Al.isAnnotationOptionsValid` → 抛通用消息 `'annotationOptions' is invalid.`）。

**实测证明是原有 bug（与本次升级无关）**：用 DDV 3.0.0 写隔离探针页（临时 `_probe_old.html`，已删）跑同一份数据：
```json
"displayType":"function", "displayDotWidth":"undefined",
"nanPoints":"THREW AnnotationManager.createAnnotation: 'annotationOptions' is invalid."
```
3.0.0 里 `display.width` 同样是 undefined、NaN 同样被拒。

### 修复
新增统一辅助函数并替换全部 6 处调用（含 `eventFunc` 里的反向换算）：
```js
async function getPageDisplaySize(pageData) {
    if (typeof pageData.display === "function") {
        try { const info = await pageData.display();
              if (info && info.width > 0 && info.height > 0) return info; }
        catch (e) { console.warn("pageData.display() failed, falling back to mediaBox:", e); }
    } else if (pageData.display && pageData.display.width > 0) return pageData.display;
    return pageData.mediaBox;
}
```
用 `displaySize.width/height` 替代 `pageData.display.width/height`。

### 附带发现并修复：`updatePage` 参数结构错误（第 6 处）
验证 Normalize 时报 `IDocument.updatePage: 'source' is invalid.`，且页面内容未变。
`IDocument.updatePage(pageUid, source)` 要求 `UpdatedSource = { fileData: Blob, fileIndex? }`，而代码传了裸 Blob。
**同样是原有 bug**：DDV 3.0.0 的实现第一行就是 `const { fileData: o } = e`，也要求对象。
已改为 `await currentDoc.updatePage(currentPageId, { fileData: blob });`

### 实测结果（全部通过，控制台零 error）

|---|---|---|
| 坐标换算 | `NaN` | `{125,29} {737,67} {716,988} {15,933}`，有限且在 mediaBox 内 |
| `createAnnotation` | THREW | `OK uid=...` |
| UI 点 Detect | 无注解 | 创建 `polygon`（name=`document`），坐标与 CV 输出一致 |

证据截图：`.workbuddy/artifacts/detect-quad-annotation.png`（蓝色检测边框）、`detect-normalize-fixed.png`（矫正后页面）。
